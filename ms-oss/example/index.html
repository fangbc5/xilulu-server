ms-oss 开发者接入指南

学习如何在前端完美对接后端 OSS 服务。全程透明，告别黑盒。

🚀 业务流一：核心文件上传机制

1
向业务后端索取「预签名直传授权 URL」

核心原理：后端不直接接收文件流，减轻带宽压力。前端通过此接口，把想要上传的文件信息告诉后端。后端校验通过后，会使用底层 OSS 引擎签发一个独一无二、带过期时间的临时上传 URL 凭证返回给前端。

POST /oss/signature
2
拿着授权 URL，向 S3/MinIO 直接发起上传

核心原理：使用原生的 PUT 方法，将文件主体直接送到 MinIO / 阿里云。这里极容易因为 MinIO 没放行 CORS 而失败！浏览器强制跨域策略，文件根本到不了服务器。

⚠️ [常见错误] 如果下一步卡在 Network / CORS error：
说明你的 MinIO 容器尚未允许浏览器直传跨域，导致请求在浏览器侧被拦截。
请在本地用 Docker 执行: docker exec fbc-minio sh -c 'mc alias set myminio http://127.0.0.1:9000 minioadmin minioadmin && mc admin config set myminio api cors_allow_origin="*" && mc admin service restart myminio'
PUT <签发的海量临时参数URL>

🔗 业务流二：文件授权与分享

4
长效分享及文件处理展示

背景：大部分私人文件不可直接公开。通过服务端下发包含特定有效期的 JWT Token 令牌进行动态转发（302 跳转），不仅能控制分享链路的生命周期，还能在URL请求中挂载 图片处理参数 唤起后端实时图像引擎。

POST /oss/signature
GET /oss/share/{token}
