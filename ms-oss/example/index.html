业务流一：单文件预签名直传
1

获取预签名上传凭证

POST /oss/signature

客户端将文件信息提交给后端，后端校验场景规则后签发一个带过期时间的临时上传 URL 凭证。文件流不经过后端，直传到 MinIO/S3。

2

向 MinIO/S3 直传文件

PUT <presigned_url>

使用 Step 1 拿到的预签名 URL，通过 PUT 方法将文件体直接发送到 MinIO。这一步完全绕过业务后端。上传完成后 MinIO 自动通过 Kafka 通知 ms-oss 落库。

⚠️ 如果上传失败报 CORS 错误，请执行：
docker exec fbc-minio sh -c 'mc alias set local http://127.0.0.1:9000 rustfsadmin rustfsadmin && mc admin config set local api cors_allow_origin="*" && mc admin service restart local'

业务流二：图片处理 & 长效分享
3

图片实时处理 (imgproxy)

GET /oss/{bucket}/{key}?x-oss-process=...

通过 x-oss-process 参数指定图片处理指令，ms-oss 会将请求 302 重定向到 imgproxy 进行实时处理。支持 resize/crop/format/quality 等操作。也可使用预设 Style 简化参数。

↑ 302 重定向到 imgproxy 的实时处理结果

4

长效分享链接 (JWT Token)

POST /oss/signature GET /oss/share/{token}

签发一个包含 JWT Token 的短链接。访问时 ms-oss 解码 Token 后 302 到真实资源。支持绑定图片处理参数，防篡改。适用于聊天消息中的图片展示。

↑ 通过 JWT 分享链接加载的图片

📋
业务流三：元数据查询 & 文件删除
5

查询文件元数据

HEAD /oss/{bucket}/{key}

通过 HEAD 请求获取文件的 Content-Type、Content-Length、原始文件名、业务场景、缩略图 Key 等元信息（返回在 HTTP Header 中）。

6

删除文件

DELETE /oss/{bucket}/{key}

删除 S3 中的文件并软删除 file_meta 记录。如有关联的缩略图也会一并清理。

⚠️ 此操作不可逆。删除后上方所有预览链接将失效。
📎
业务流四：大文件分片上传
7

分片上传全流程

POST ?uploads PUT parts POST ?uploadId

适用于大文件（视频/大型文档）。流程：InitiateMultipart → 逐片直传 → CompleteMultipart。每片独立使用预签名 URL，支持断点续传。
